# 06 · Test Scenarios & Edge Cases

Six scenarios: 1 happy path, 4 edge cases (the brief asks for 2–4 non-trivial ones), and 1 bonus. All data is synthetic, generated by `scripts/make_samples.py`; GSTINs carry valid checksums. These are both the **demo script inputs** and the **regression tests** (`tests/test_scenarios.py`).

> ⚠️ **Order matters:** run #2 **before** #5. Scenario 5 is the resubmission of #2 (same ref `VS-2026-102`). Run alone, #5 is a perfectly clean submission and gets APPROVED, which is itself a good talking point: *"the fraud signal isn't in any single submission, it's in the behaviour across versions."*

## Scenario 2 · Edge 1: Cross-field inconsistencies (Ridgeway Packaging)

**Why it's non-trivial:** a field-by-field validator approves this. The PAN is well-formed. The GSTIN has a valid checksum. The problems only exist *between* fields.

| Field | Value | Trap |
|---|---|---|
| ref | VS-2026-102 | |
| PAN (form) | **AAACR7731P** | typo: the real PAN is AAACR7781P (one char) |
| GSTIN | 29AAACR7781P1ZG | embeds AAACR7781P; state **29 = Karnataka** |
| Address | Unit 4, Hinjewadi Phase 2, Pune, **Maharashtra** 411057 | GST is per-state; this is the Karnataka branch's GSTIN |
| Bank | Ridgeway Packaging Pvt Ltd · 441705001122 · ICIC0004417 · ICICI Bank | fine |
| Docs | GST cert (Karnataka, AAACR7781P) · PAN card (**AAACR7781P**) · ICICI cheque | PAN card confirms the typo direction |

**Expected:** PENDING · Awaiting vendor · risk 36. Three specific asks:
1. PAN vs GSTIN differ by one character, *and your PAN card shows AAACR7781P, matching the GSTIN, so the form entry looks like a typo*
2. GSTIN is Karnataka (29) but the address is Maharashtra → share the Maharashtra GSTIN (should start with **27**) or update the address
3. PAN card shows AAACR7781P but the form says AAACR7731P

**Demo line:** "It classified documents by content, not filename. It caught the sister-company GST certificate, the missing cheque, and the extra PAN card uploaded in the cheque slot."

## Scenario 5 · Edge 4: Resubmission bank swap (Ridgeway v2) ⭐ strongest edge case

**Why it's non-trivial:** every single check on this submission passes. Every document is consistent, including a new cheque for the new account. The only signal is **behavioural**: across versions.

| Field | v1 (scenario 2) | v2 (this) | Requested? |
|---|---|---|---|
| pan | AAACR7731P | AAACR7781P | ✅ asked |
| gstin | 29AAACR7781P1ZG | 27AAACR7781P1ZK | ✅ asked |
| bank.account_number | 441705001122 | **021963700004412** | ⚠️ **never asked** |
| bank.ifsc | ICIC0004417 | **YESB0000219** | ⚠️ never asked |
| bank.bank_name | ICICI Bank | Yes Bank | ⚠️ never asked |
| contact.phone | 9822012345 | 9822012345 | unchanged |

Docs: ridgeway_gst_certificate_MH.pdf (27…), ridgeway_pan.pdf, ridgeway_cancelled_cheque_yes.pdf (matches the new account).

**Expected:** PENDING · **Compliance review** · risk 35 · fraud signal RESUB_BANK_CHANGE.
Vendor email: neutral "under review… we may call you on the number originally registered" (no tip-off).
Internal note: "…classic account-takeover / BEC pattern. Hold. Verify by calling back on the ORIGINAL number on file (9822012345)…"

**Demo line:** "It classified documents by content, not filename. It caught the sister-company GST certificate, the missing cheque, and the extra PAN card uploaded in the cheque slot."

## Automated tests (`tests/test_scenarios.py`) must assert

1. Each scenario 1, 2, 3, 4, 6 run standalone → expected `status` and `queue`.
2. Scenario 2 then 5 with `previous` = result of 2 → PENDING / Compliance review, and `RESUB_BANK_CHANGE` failed.
3. Scenario 5 standalone → APPROVED (documents the behavioural nature).
4. Scenario 3's vendor email body does **not** contain "V-1042" (internal vendor-master context must never leak to the submitter), while its internal note **does**.
5. Every sample GSTIN: our checksum == `stdnum.in_.gstin.is_valid`.
6. Document classification: `vertex_cancelled_cheque.pdf` → `pan_card`; every other file → the type in its name.
7. `normalize_name("A.B.C. Pvt. Ltd.") == normalize_name("ABC Private Limited")`.

## Manual / exploratory cases to try in the UI (not in the demo)
- Blank form → REQ_FIELDS lists everything; nothing crashes.
- GSTIN with the last char changed → checksum failure naming the expected char.
- Entity "Private Limited Company" with a P-type PAN → PAN_TYPE blocker.
- Re-run scenario 1 twice → v2, RESUB_DIFF "Changed: nothing", still APPROVED.
- Upload a random non-government PDF → DOC_UNKNOWN warning.
