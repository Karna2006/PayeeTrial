# 13 · Testing pipeline and fixture guide

PayeeTrail's checks should be repeatable without an OpenRouter key, a local model server, live government services, or real vendor records. The CI job builds the synthetic fixtures and runs the same pytest suite on every push and pull request.

## Run tests locally

```powershell
# from the repository root, after installing requirements.txt
python scripts/make_samples.py
python scripts/make_scan_sample.py
python -m pytest -q
```

The fixture generators write six scenario JSON files, 17 synthetic scenario PDFs, one separate image-only scan PDF, and a six-row synthetic vendor master. Run `python scripts/make_scan_sample.py` to recreate `samples/docs/synthetic_scan_pan.pdf` for a manual OpenRouter OCR check. The fixtures contain only fake values and are safe to regenerate. Never place real PAN cards, GST certificates, cheques, account numbers, or API keys in `samples/` or `tests/`.

If pytest cannot access the machine's temporary directory, direct its temporary files to a fresh directory under the repository (pytest clears the selected `--basetemp` directory before using it):

```powershell
$testTmp = Join-Path (Get-Location) ('.pytest-tmp-' + [guid]::NewGuid().ToString('N'))
python -m pytest -q -p no:cacheprovider --basetemp $testTmp
```

## Test layers

| Layer | What it covers | External credentials/services |
|---|---|---|
| Scenario regression | All six expected decisions, risk/queue, cross-field findings, resubmission order, duplicate bank detection, vendor/internal message separation, fixture validity | None |
| Rule and decision edges | Missing fields, malformed IDs, checksum/state mismatch, PAN type, account-name thresholds, duplicates, severity precedence, requested vs unrequested changes, deterministic results | None |
| Document intake | Content-based classification, wrong document under a misleading filename, unreadable/encrypted/oversized/over-page PDFs, blank/image-only PDF handling, missing/mismatched required documents | None |
| Document AI boundary | Valid structured result, invalid inputs and schemas, wrong-page or unsupported evidence, provider errors, scan-only review hold, classifier conflict, prompt-injection text, score-evidence caps, and protection against AI fields replacing local rule inputs | Mocked OpenRouter responses only |
| Analyst workflow | Required reviewer, reason, and original-PDF acknowledgement; corrected values rerun deterministic checks; AI candidate remains intact; append-only event does not increment submission version | Synthetic document values only |
| Upload autofill | The explicit button runs local extraction or optional OpenRouter OCR; cited AI values can fill blanks; existing values remain untouched; conflicting sources are surfaced rather than selected | Synthetic PDFs and mocked AI evidence |
| Duplicate screening | SHA-256 catches a byte-identical PDF renamed before upload; distinctive near-duplicate company names enter review, never auto-reject | Synthetic vendor master only |
| Streamlit UI and storage | Page boot, required-field/document gating, sample loading, scenarios, resubmission, reset, SQLite isolation and history | No OpenRouter key or local model service |

## Existing safe test data

Use `samples/01_*.json` through `samples/06_*.json` and `samples/docs/*.pdf`. The scenarios cover a clean company, cross-field PAN/GSTIN errors, a third-party bank account, wrong documents, a suspicious bank change on resubmission, and a legitimate proprietorship. The files are generated by `scripts/make_samples.py`; they are not documents from the repositories linked for architectural inspiration.

The AI boundary suite uses the generated image-only PDF and mocked structured responses. It verifies scan detection and manual-review routing without sending data to Google. To measure real OCR/classification quality, use only synthetic or explicitly authorized, redacted test documents and record expected fields and page numbers independently.

## GitHub Actions

`.github/workflows/tests.yml` runs on pushes, pull requests, and manual dispatch for Python 3.11 and 3.12. It installs `requirements.txt`, regenerates the synthetic corpus and scan fixture, and runs `python -m pytest -q`. The workflow has no API key and makes no provider calls; OpenRouter parsing and error handling are tested with mocked responses.

## Manual demo test after a local run

1. Start the app with `streamlit run app.py`; upload one selectable-text PDF, click **Autofill fields from documents**, and confirm blank matching fields fill without changing values already entered. Check that AI options are disabled until `OPENROUTER_API_KEY` is configured.
2. Run scenarios 1, 2, 3, 4, and 6 individually and compare outcomes with `docs/06_TEST_SCENARIOS.md`.
3. Run scenario 2, then scenario 5 with the same reference; confirm v2 routes to Compliance review for the unrequested bank change.
4. In a separate run, enable AI document review and add `samples/docs/synthetic_scan_pan.pdf` as an additional PDF alongside a complete scenario. Confirm its candidate remains in analyst review, download/check the original, record the reviewer and reason, then confirm the rerun uses the accepted fields while preserving the original AI output and submission version. Use only synthetic documents with the free endpoint.
5. Try a corrupted PDF, a password-protected PDF, a PDF over 10 MB, a PDF over 40 pages, and a valid PDF with no selectable text. Each should produce an explicit warning or review item rather than crash.

The real-provider check in step 4 is a manual smoke test, not a deterministic CI assertion: model output can vary. Never use the provider call to determine whether the deterministic rules suite passes.
